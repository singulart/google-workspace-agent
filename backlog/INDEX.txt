Context budgeting (design)
--------------------------
MCP char budgets bound a single tool result only. They do not see AgentCore
Memory / STM already merged into the agent prompt. Total context safety requires
agent-side limits (TASK-F4) plus conservative hydrate defaults (TASK-B5).

Required (v1):
  - TASK-B5: message_limit + per-message max_body_chars (hard ceiling)
  - TASK-F4: Strands window + filter_restored_tool_context when MEMORY_ID set

Optional (phase 2):
  - TASK-B6: global total_max_chars across threads in one get_threads call
  - TASK-F3: automated MCP output size regression suite (depends on B6 for
    global-budget scenarios; per-message caps testable after B5 alone)

Definition of done (all tasks)
------------------------------
- Unit tests added/updated; pytest passes
- No message bodies in logs or trace attributes
- Public behavior documented if user-facing
- Single responsibility: task does not bundle unrelated refactors

Primary repo: gmail-dwd-mcp-server (MCP tasks)
Secondary repo: gmail-agent (agent integration tasks)

Design: LLM-only read path
--------------------------
- search_threads -> TriageThread (snippet + headers, no body)
- get_thread / get_threads -> HydratedThread (body = normalized plain text)
- No FULL_CONTENT, no messageFormat on read tools
- threads.get(format=full) is Gmail API fetch only (internal)

Out of scope (separate backlogs)
--------------------------------
- Async pre-indexing / search store (OpenSearch, DynamoDB)
- Attachment content extraction
- Thread summarization via LLM inside MCP server
- Per-tenant SSM policy overrides beyond env config
